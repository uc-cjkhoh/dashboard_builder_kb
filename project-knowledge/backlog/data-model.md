# Backlog: data source

Data-source work not yet built. Entries are in dependency order. Format: [README.md](README.md#how-to-read-an-entry).

Relationships are logical, inner/left/right/full, with one equality pair each ([relationships.md](../features/data-source/relationships.md)). Rules for new work:

- A union compiles to `UNION ALL` with explicit column alignment.
- Unpivot and split compile to ClickHouse array and string functions.
- Source tables are never altered.
- Null, empty string, zero, invalid date and non-finite number stay distinct.

- **Compound joins and key suggestion: remainders** (IDs: T02-14, T02-15; priority P2) — Partial: a relationship can match on up to four column pairs (ANDed), with matching-name, same-kind suggestions for the extra pairs in the relationship dialog ([relationships.md](../features/data-source/relationships.md#compound-keys-and-key-suggestion), [D79](../reference/decisions/decisions-dashboards.md#d79--a-compound-join-key-is-the-first-pair-plus-up-to-three-extra-pairs)). Open: no suggestion for the first pair (the column to drag or pick: a table's best-matching columns are not highlighted while relating); extra pairs are added only in the dialog, not by dragging or relating two more columns of already-related tables; no suggestion by other signals (a `_id` suffix against `id`, a primary-key or sorting-key hint, matching values); more than four pairs, and a pair of unlike kinds through a cast, are refused. Needs: none.
- **Union and unpivot as a source: remainders** (IDs: T02-16, T02-31, T02-32; priority P1) — Partial: a union and an unpivot can be added to the Data Source and read by worksheets ([query-sources.md](../features/data-source/query-sources.md)); the unions' columns are matched by name and kind only, and a card says so. Open: a union or unpivot can't be joined to another table or take a relationship (a view reads only that source); no manual alignment of differently named union columns, no rename, no mismatched-fields view; tables of one database only; a source can't be edited in place (remove it and add it again), and its name is automatic; no Show rows, column profile, histogram, box plot or approximate sample over a source; no unpivot of mixed-kind columns, no rename of `Field` / `Value`, no pivot back. Needs: a decision on what a relationship to a source means (join keys on a derived table).
- **P43 Many-to-many and two-way relationships** (priority P1; effort M) — Open: cardinality is recorded but every link is one way (the join type is per relationship). Aggregate each side to the shared key before joining so measures do not double-count; add a per-relationship filter direction. Needs: none.
- **Member labels and groups: remainders** (IDs: T02-29, T02-30; priority P2) — Partial: member labels (display-side) and text-field groups, with an "Other" label for ungrouped members (a generated calculation tree), are built ([worksheet.md](../features/worksheet/worksheet.md#layout), [calculated-fields.md](../features/worksheet/calculated-fields.md#group-fields)). Open: groups on number, date and true/false fields (the engine compares text only; numeric ranges and date bins would need `IN` / range nodes); more than 49 members across a field's groups (48 with the "Other" label; the 200-node limit; needs an `in` node on the server); a way to group NULL (the remainder label leaves NULL empty); making a group from the marks selected on a chart (Tableau's group icon); labels for calculated and group dimensions, date-part keys, bucketed numeric keys and Pages; groups on UUID, IP and enum columns (a `toString` branch), and a selection chip that follows a label edit; one label set shared by a field's group field and the field. Needs: none.
